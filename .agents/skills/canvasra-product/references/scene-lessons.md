# 场景制作与验收经验

本文件用于后续 CANVASRA 商品任务。依据 2026-09-07 Mineral Tides 与 Quiet Inscriptions 的实际反馈；不是当前商品已修复的证明。

## 先定展示方式，再生成背景

- 新任务移动端场景使用原生 4:5，PC 首屏另做 3:2；旧任务保留原比例，正方形原作仍保持 1:1。不要混淆画作比例、背景比例、图库窗口与灯箱比例。
- 旧方形背景放入竖版窗口会产生上下留白；透明 Header 会透出留白，不能靠改透明度解决。新背景须铺满窗口，灯箱保留素材原比例。
- Header 首屏完全透明、保持现有深色 Logo/图标，无渐变、无自动变色；滚动后实色。顶部留出干净且足够明亮的墙面，检查画框、窗框、枝叶是否穿过导航。实际手机截图是验收依据，不能仅检查 CSS background=transparent。

## 大尺寸是视觉结果，不是文件名

- 三个场景中至少一个呈现明显大画效果；每次扫描图库，大尺寸优先查看 bigsize 子目录（大小写不敏感）。实际参考图要传入生成工具，并保存来源与选择依据。
- 横画、竖画、方画分别规划画作与家具关系，不统一套“长边占高度65%–75%”。约70%宽的方画只是本次构图实例，不是全部商品的固定参数。
- 不能仅靠缩小家具、拉远房间或放大整张截图冒充大尺寸。镜头取景可以裁去部分家具，但必须保留可信尺度线索和合理挂画位置。
- 背景必须匹配已上线渲染布局。生成前核对线上实际代码；本地已有新布局不代表线上支持，不能上传后才发现背景为空或画仍很小。

## 真实感必须单独验收

1. **墙面透视**：通过墙角、踢脚线、窗框等线索判断挂画平面。当前正面叠加适合正对墙面；家具斜放不等于墙也斜。无法确认时记录不确定性，不把“贴图感”直接归因于墙斜。
2. **光线一致**：核对窗户/灯光方向、软硬、明暗与色温。强侧光背景配均匀正面画框容易显假；当前渲染不支持匹配时优先选柔和均匀的背景，不添加更强光照矛盾。
3. **贴墙关系**：框边、局部接触阴影和离墙投影应连贯，避免悬浮、统一发光边或生硬黑影。阴影方向与强度由房间光源决定，不能统一加重阴影当作修复。
4. **边缘与材质**：画框锐度、反光、侧边与房间的清晰度相容，检查是否像贴上去的薄片。不得为真实感夸大实体颜料厚度。
5. **空间关系**：检查整幅画与靠背、灯具、窗帘、枝叶的遮挡和间距，尤其是大画下沿。大画不能只是勉强没碰到家具。

修正顺序：先选适配的背景与取景，再调整允许的挂画位置，最后处理已有渲染能力范围内的框边和阴影。需要透视变换时必须让画、框、阴影作为完整组合一致变换；不单独倾斜原作，也不把原作与画框烘焙进可换框背景。超出当前能力时明确缺口，并准备可审查的修复；主题部署仍按仓库授权规则。

## 验收记录与自动执行

- 查看真实合成图：手机端正常观看尺寸、灯箱大图，以及所有实际出售框色。黑框、白框和金属框尤其可能暴露合成边缘。
- 分别记录比例/媒体/变体等技术检查，以及透视、光线、贴墙感、构图等视觉检查。API READY、测试通过、图片解码成功，都不能证明画面真实。
- 未检查的效果不能写“已验证”。本次 Quiet Inscriptions 首次验收通过了尺寸与遮挡，却漏检光线和贴墙感；保留这条失败记录，不把旧通过记录当作以后复用的质量证明。
- 用户长期授权自动接受素材；视觉失败由 Codex 自行修正、保留新旧版本、复验后继续，不再询问主图是否接受。生产事实、价格和主题部署权限不能靠视觉推断。
- 肌理识别由 Codex 自主判断，侧面图有新增信息才生成；真实裁切细节来自同一主图，生成侧视图明确为设计示意。
- 完成前查看真实线上首屏和场景，核对已部署版本，区分“已发布”“技术验证通过”“视觉验证通过”。


## 光影预检与修复流程（2026-09-08）

新建商品采用 lighting-v1；这是创建流程升级，不表示主题已经具备逐房间光影参数，也不是旧商品视觉已修复的证明。

1. **先看参考，再定光线。** 每张参考分别记录窗/灯的位置、投影方向、软硬、墙面透视、画框应有的亮暗边和背景锐度。区分观察与推断，不确定就写明。不能仅用“高级、真实、电影感”等风格词代替观察。
2. **与真实渲染能力对齐。** 当前画框使用均匀材质和无水平偏移的柔和向下投影；尚无逐场景方向阴影和框面重照明。优先选宽大柔光、正面墙。强侧窗参考可保留家具布局，但须把光线调整为可信的宽泛正面/上方漫射光，墙、家具和地面一起调整；不能保留强侧光斑却要求画框忽略它。无法可信调整时换参考，不继续烧生图次数。
3. **给模型两种明确角色的参考。** 已接受 master 决定场景的情绪、视觉重量与配色方向；房间参考提供可选择的摄影、光线和材质依据。家具、墙面与镜头按作品重新设计，记录保留与舍弃的参考元素。输出依旧是空背景，禁止烘焙原画、画框、白卡纸、框轮廓或矩形框影；消除原参考移除挂画后遗留的阴影。保留自然墙面细节，不能靠模糊背景或重绘原作掩盖贴图感。
4. **按最终挂画范围留空间。** 普通场景 x23–77%、y14–58%；大场景 x10–90%、y0–78%；PC x28–72%、y20–70%。除完整挂画范围，还给柔影留余量。大场景家具原则上低于82%，再按实际合成检查。手机顶部须让实际画框避开Header；仅满足“顶部12%亮墙”不是通过证明。
5. **空背景和挂画结果分别检查。** 用当前主题真实的 artwork-scene/frame-preview 合成，保留默认框大图与所有实际可售装裱的标记对照图；原作、背景、参考都保留。按透视、光向、接触阴影、离墙投影、框面受光、清晰度、遮挡间距、原作完整性八项记录 pass 和具体观察依据。任何项看不清或任一框色失败，都不能接受该素材。卡纸不能移植到油画浮框，浮框应表达真实间隙而非摄影白边。
6. **按原因修复。** 家具遮挡、硬光、墙面角度属于背景问题；将上一次失败背景也作为参考，只修缺陷，保留成功构图。柔影悬浮、框面没有合理明暗等若来自主题能力，则保留图片并停止自动重生，处理可审查的渲染方案后用同一背景复验。原因不明也不盲目重生。不要用阴影加黑/加粗替代定位问题。
7. **PC与手机各自验收。** 同房间横竖两种构图共享光线逻辑；手机4:5、PC3:2不能直接裁一刀。核对桌面16:9/16:10裁切下的完整画作、家具和Header。Studio自动对照图是本地场景渲染，不能替代 agent-browser 对最终页面的检查。

Codex任务把计划与截图/文件哈希写入任务目录 `scene-lighting-plan.json` 与 `scene-review.json`，spec中记录 `sceneWorkflow: lighting-v1` 和证据路径；接受素材时引用实际检查结果。自动接受授权不代表可省略审核。没有实际生成/视觉验收时，只报告流程代码完成。

Product Studio新任务自动保存 sceneWorkflow，旧任务缺少此字段时仍按原流程恢复。每张新背景多一次光线分析与一次多框视觉复核；仍遵守既有模型和费用授权。失败背景重试不超过maxAttempts；结果不明的外部请求不自动重发。已生成但未完成验收的图片先复用验收，不直接再生一张。


## PC Banner 制作与替换规则（2026-09-08，优先于上述旧PC条款）

新任务使用 `bannerProfile: fullbleed-v2`，按[完整Banner制作与验收契约](../../../../docs/PRODUCT_BANNER_RULES.md)执行。原生21:9背景、独立v2挂画布局、全屏cover以及突破1920px页面上限必须配套；不要再沿用旧3:2小挂画区或超宽屏contain。该比例是本店适配方案，不冒称参考网站的图片比例。先计算实际画作占位，再生成背景；须检查四种屏幕和全部装裱的真实合成，视觉不通过不得上传。已有商品按版本保留，替换先备份。新版主题未部署时保留本地素材并明确阻断，不上传空背景。
