# Product Studio：当前实现与使用

2026-10-03 场景风格预设：新建任务可选「场景风格」（默认自动按画作搭配），预设定义在 `scripts/product-studio/scene-styles.js`（明亮极简白、暖调木色、深色画廊、柔和中性、复古摩登），批量创建可逐张覆盖。选定风格后三层提示词同步收敛：场景方案必须留在该风格族内（MANDATORY 指令）；图库粗筛、精选、补选与跨图库终选按风格偏好取舍参考（风格契合优先于配色契合）；场景生成由「参考线索可改编」改为贴近参考图的家具风格、材质与配色，仅为画作自身比例、留白带、光线一致性与输出比例做必要调整。不选风格时全流程保持原有 artwork-led 行为。任务卡片与场景方案面板显示风格徽章；选图缓存上下文包含风格 id，更换风格不复用旧选图回执。

2026-09-14 店主要求直接重试：生图异常点击「重试此图」直接排队，不再弹窗填写核对依据，也不因已有服务商回执而拦截。旧请求标记 superseded，回执和已完成素材保留；不声称旧请求未生成。此规则取代此前强制填写依据的要求。

2026-09-13 异常恢复按钮按未确认请求分类：分析显示重新分析；生图显示查询结果与重试此图，查询仅检查本地回执并提供请求时间，不冒充服务商远端查询，重试需无结果依据且有回执时拦截；仅 Shopify 请求显示核对 Shopify。未知或混合请求不自动归类。恢复保留已有素材与历史请求记录。

2026-09-13 参考类别自动补齐：终选前保证至少两张普通参考和一张 Bigsize；普通参考不足时按批扩大到普通图库，补选回执可复用。补选为空时将该类别完整图库交给终选比较与房间适配，不因模型空选直接停工。终选返回重复图片或不合法类别时，自动改为逐场景、限定类别并排除已选图片的选择。不会凭目录顺序直接采用图片。图库物理缺失、模型持续返回无效结构或网络故障仍可能需要处理，不宣称任何图库都必然存在审美匹配。

2026-09-12 创建后自动开始：单张和批量新建统一在服务端保存参考图后进入 queued，由现有单任务调度器自动开始。网页按钮为「创建并开始」，不再额外发送 run 请求，也不需要再点一次开始；已有任务运行时自动等待。历史暂停、失败或待核对任务不随此修改自动恢复。

2026-09-12 最新场景框色：店主取消白框，仅使用 Oak 橡木和 Black 黑色，仍按作品与房间搭配，并与商品实际可用选项取交集。frameSelectionPolicy=artwork-fit-v3，旧三色方案的 frameAndScale 不直接带入后续生成；PC 延续场景三的允许框色。该要求取代下文较早的三色、五色场景范围。商品购买选项和已有图片保持不变。

2026-09-12 店主收窄场景框色：仅在 Oak、Black、White 中按画作和房间搭配选择，并与商品实际可用浮框选项取交集；不再选择 Gold、Silver、Walnut。frameSelectionPolicy 升为 artwork-fit-v2，旧五色方案中的框色指令不直接带入后续生图。PC 延续场景三的允许框色。该限制只用于场景生成，商品购买选项和已有图片不变，取代下文较早的场景颜色范围。

2026-09-12 场景框色按作品搭配：烤框提示词不再固定 light-oak。场景方案的 frameAndScale 从该任务已核实变体中的浮框颜色选一款并说明搭配理由；保存 frameSelectionPolicy=artwork-fit-v1，生图继续受同一选项列表约束。当前标准为 Oak、Black、White、Gold、Silver，只有商品实际提供时才纳入历史 Walnut。不同房间可分别选色，不强制换色；PC 沿用场景三中可用的框色。旧方案保留原记录，但后续重做不会直接带入旧 frameAndScale 的固定橡木指令。只影响后续生成，不重绘已保存图片，不改变顾客的购买框型或商品变体。

2026-09-12 任务删除：卡片和详情页均可一键「删除任务」，从工作台的全部、待处理、已完成等列表与计数中移除。采用 deletedAt 标记，原图、素材版本、外部请求回执、商品 ID 与操作记录仍留在原任务目录，不删除 Shopify 商品。排队任务删除后不再被调度；运行中的任务需先暂停并等当前步骤结束。删除接口幂等，已删除任务不能继续、重做或发布，重启后也不会回到列表或恢复执行。维护时可用 Store.list({includeDeleted:true}) 查看保留记录。

2026-09-12 场景比例提示词优化：场景方案与最终生图统一读取当前主画的实际宽高，缺少尺寸的旧任务才回退到 analysis.ratio。明确画作宽高只能同比缩放，画作比例指框内完整画面，4:5 / 21:9 仅指整张场景。房间参考（包括 PC 使用的场景三）不提供画作比例；以独立主画重建，避免沿用参考中的变形。场景不再传入主画生成阶段的 masterPrompt，防止“调整比例 / 重新创作”要求混入。保留三个场景的大小区别、宽画的竖版宽度上限及场景二的轻微侧视；空间不足时调整房间、镜头或家具，不能单独增减画作宽或高。这些是生成约束，不能保证模型每次遵守；不增加自动定位、视觉审核或自动重生。仅用于后续生成和人工重做，已有图片保持原样。

2026-09-12 重做与恢复修正：所有人工重做（含主画）完成后进入 scenes-ready 等待确认，不创建或发布 Shopify 商品；“确认图片并上架 / 确认图片并保存草稿”沿用原 target，初次自动发布不受影响。场景三重做会同步使依赖它的 PC 图失效，界面显示两张；PC 图保存 sourceSceneHash，恢复时核对旧 referenceHashes 或新来源哈希，发现来源变化则重做 PC 图并等待确认。格式恢复改为 ModelFormatError 类型，原始请求最多补问两次，向相同分析请求反馈具体缺失字段；普通图片、文件和店铺错误不按文本误重试，结果不明仍按原规则核对。

2026-09-12 更新：新带框场景（baked-frames-v1）已取消自动画作边界定位、框内比例测量及其发布拦截。仅检查文件完整性、整张图片比例、哈希与素材来源，视觉效果由店主判断；以下较早的比例定位说明已被本条取代。历史无框叠框任务仍保留坐标定位。已有图片恢复时复用原文件，历史测量记录保留，不自动重做或发布任务。

2026-09-12 比例核对转人工：烤框场景的框内画作比例测量（正面 10%、scene-2 侧视 25%、模型拉伸判断）改为提示记录——偏差写入任务记录并在素材上显示，不再拒绝、不停工。每张场景图下方新增「比例不对，重做此图」选择器（无 Shopify 商品时可用）：可勾选多张后点「开始重做」一次执行，旧版本保留。凡出现比例偏差标记的任务，即使选择了自动发布，也会在创建 Shopify 草稿前停在「发布前复核」；店主确认满意后点「上架到 Shopify」完成发布，标记只在显式发布时清除。定位不出画作仍是程序失败。同日从源头压制宽画变形：宽幅画作（如 3:2、2:1）在竖版场景的生成提示词中加入宽度上限（约 36–52% 视比例而定）与禁止纵向拉伸的明确指令，仅作用于竖版场景（桌面 21:9 横版不适用）；跨图库终选对宽画优先选择宽墙面参考。2026-09-11 场景视角放开（scene-2）：正面视角本是叠框契约的要求（坐标映射与像素边缘校准需要近正面画边），烤框契约下已无此必要。现在烤框任务的 scene-2（小角落私密场景）允许约 30° 内的轻微侧视，提示词要求四框边完整可见、内容清晰、禁止广角畸变；scene-1/scene-3/桌面首屏保持近正面，保证画作可读性。配套变化：画作比例核对改为视角感知——正面维持 10% 容差，侧视放宽到 25% 并由模型对照原作判断画作是否被拉伸/压扁（是则拒收）；场景方案（art-direction）、批次初选与跨图库终选的提示词同步允许 scene-2 选用轻微侧视的参考图。composed 叠框旧流程的提示词与检查一律不变。

2026-09-11 批量建任务与图库档案：新建产品可一次多选参考图（最多逐张 20MB），提交后逐个创建并入队，后台按现有机制依次执行；批量任务共享创作说明、场景偏好与发布目标；创作方式（参考创作/保留提取）与交付范围在多选时按图逐张设置，单张失败不影响其余。选图侧新增全局「图库档案」：参考图超过 24 张时，先用一次联系表描述把每张参考的房型、视角、墙面、配色与密度存入跨任务共享的 `library-index.json`（按文件内容哈希增量更新，改动/新增的图才重新描述；建档调用记在首个需要它的任务名下），之后每个任务先用档案文字粗筛 12–24 张候选（纯文本调用），再对候选拼一张联系表做一次视觉精选，最后照旧跨候选终选——大图库每个任务的视觉调用从「每 12 张一批」降到约 2 次。24 张以内的小图库维持原批次选图流程不变；粗筛与精选的回执同样按上下文哈希缓存，任务恢复不重复付费。

2026-09-11 提取模式禁裁边：参考原作与目录比例不完全一致时，生图模型曾自行裁掉边缘内容（实例：最右一列被切掉一部分）。现在 extract 主图提示词固定权衡方向：比例不符时允许对整幅画作做轻微整体比例调整，禁止裁切、收窄或省略任何边缘内容，最外侧笔画必须完整可见；create 模式无此约束。

2026-09-11 创作强度修正：「参考创作」模式此前在分析与主图两处仅有一句宽泛的 inspired-by 指令，配合直送的参考原图，产出几乎等同提取。现在分析与主图提示词按模式互斥注入：创作模式明确要求仅保留主题大类、媒介与整体氛围，构图、视角、元素排布、背景与调色诠释必须重新设计，禁止复制参考图的布局、姿态、比例与元素位置；提取模式的忠实保留指令不变。

2026-09-11 场景契约切换：新任务采用烤框完整场景（sceneWorkflow=baked-frames-v1，媒体 alt `composed-framed-scene-*-v1`）。场景生成时把所选浮框直接画进画面，一槽一图，不再提取画作坐标或写入 custom.scene_layouts，也不做按框色的重着色。发布门槛按任务检查在线标记：烤框任务查 baked-frames-v1，历史无框任务查 composed-frames-v1；主题两个标记同时输出。

2026-09-09 尺码与定价更新：新任务默认使用已确认的完整交付组合（含卷装），可显式选择特殊工艺仅装框；历史任务已保存的交付选择保持不变。六比例实时草稿和 `data/pricing/mesonart-catalog.json` 共用标准，按每个方向、尺寸、框型的 Mesonart 样本众数取实际美元标价，不复制活动折扣。详见 [PRICE_TABLE.md](PRICE_TABLE.md)。

2026-09-10 定价结构修正：Studio 上架必须写入店内统一的促销结构 —— 偏移后的表价是标准原价（`compareAtPrice`），售价固定为其 60%（`salePrice`）；偏移 key 取**任务 ID**，因为定价在文案与 handle 生成之前就已确定，且"发布前复核"要用同一个 key 重算比对。此前 Studio 只写 `price`（且写的是原价）、完全不带 `compareAtPrice`，导致 2026-09-10 上架的商品按原价在售且没有划线价；已按上述结构修正线上数据，并把 `compareAtPrice` 加入商品回读与 `validateProduct` 比对。

2026-09-09 更新：已在 46927c2 基础上实现本地 generation-only-v1 流程，尚未提交或部署。本文说明独立网页工作台；Codex 账本是[另一条流程](CODEX_PRODUCT_WORKFLOW.md)。

## 启动与配置

使用 Node 24、仓库指定的 pnpm：

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm studio
```

入口 http://127.0.0.1:4310，仅监听本机。后台进程运行时可以关闭浏览器，关机后不会继续。不要重复启动已有服务；进程锁用于避免同时写任务目录。缺少 Playwright 浏览器时，可通过 CANVASRA_BROWSER_CHANNEL=chrome 使用已安装 Chrome。

“模型与店铺”配置分析模型、生图模型的完整 HTTPS 端点、模型 ID 和密钥。Shopify 凭据来自忽略的 .env。模型配置及任务位于 .shopify/product-studio/；密钥不返回浏览器，磁盘未额外加密。写请求校验本机来源与随机令牌。

连接测试读取同 API 前缀下的 /models，不生成内容、不保存输入。它仅证明列表可读且包含模型，不能证明视觉、JSON、生图或比例能力。配置页会读取 Shopify 规则；启动本身不提交新的生图，但已排队任务会由后台执行。

## 新任务的完整流程

1. 上传参考，选择提取原画或创作、交付范围、草稿或发布目标；可填写作品要求、独立场景偏好，并可从预设列表选择场景风格（默认自动，批量可逐张覆盖）。
2. 分析作品，从六比例草稿与在售参照核对精确变体和可售/库存规则；金额统一读取 [项目价格表](PRICE_TABLE.md)，不复制参照商品金额。尺寸未收录、参考缺失或库存不可复制时停止。
3. 生成完整主画并进行文件、哈希与比例检查，从同一主画裁切真实细节。当前未创建商品的任务不再生成肌理图，也不通过肌理识别判断交付。
4. 保存作品专属场景方案，扫描参考库、分批初选并跨批终选。三个参考须可区分，第三个使用 Bigsize。
5. 生成三个 4:5 完整房间场景与一个 21:9 PC 场景。每个房间包含同一幅画，所选浮框直接画进画面（烤框流程）。
6. 检查原作一致性、四边完整、光影、框条与留框空间、画作视觉主次和家具相交；仅无框历史流程在模型估计边界附近进行像素边缘校准。
7. 编写英文文案，重新核对真实价格与素材依赖，按唯一任务标签建立草稿并上传六张媒体；烤框任务不写 custom.scene_layouts。
8. 回读变体、媒体 READY、尺寸、alt、顺序及集合。草稿目标完成为 draft；发布目标还需验证与任务流程匹配的在线标记（烤框 baked-frames-v1 / 历史无框 composed-frames-v1），随后激活、发布并回读 Online Store 状态。

已有任务明确保存的 16:9 或其他历史比例保持不变，不自动重做图片。新任务保存 desktopAspectRatio=21:9、imagePolicy=generation-only-v1、mediaProfile=responsive-v1、sceneWorkflow=baked-frames-v1、bannerProfile=clearance-v3、mobileSceneProfile=clearance-v2、textureWorkflow=disabled、publicationRequested=true。未保存 desktopAspectRatio 的历史任务继续使用原 21:9 / 3:2 比例，不自动迁移。实际场景标识由 sceneWorkflow 分支决定，不能因任务含旧布局字段就上传为空背景。完整媒体契约见[商品图规则](PRODUCT_IMAGE_RULES.md)。

## 状态与恢复

| 状态 | 含义与处理 |
| --- | --- |
| new / queued / running | 待启动、排队或执行中；后台逐个处理任务 |
| paused | 步骤边界暂停，保留进度后继续 |
| failed | 查看具体错误与已保存证据，处理后恢复 |
| uncertain | 外部结果不明；先核对服务商或 Shopify，不能盲目重发 |
| scenes-ready | 旧素材任务已完成；“上架到 Shopify”复用已保存素材，重新执行程序检查 |
| draft | 草稿及回读完成，可以明确转为发布目标 |
| awaiting-theme | 草稿与媒体已就绪，线上缺少与任务流程匹配的场景标记（烤框任务查 baked-frames-v1，历史无框任务查 composed-frames-v1）；部署另需授权，之后继续发布并复用商品 ID |
| published | 已发布任务只读，修订需新任务 |

每张素材每次只提交一次生成，不进行 AI 质量审核、评分、驳回、自动修复或自动重生。生成成功并通过文件/哈希/比例检查就继续；不满意时手动“重做此图”。程序检查失败保存图片并停止该槽位，不自动花费额度重做。

autoRecovery 只保留分析/选图/文案/坐标提取的有界传输与格式恢复，旧 maxAttempts 不再控制图片重生。生图或 Shopify 结果不明仍需核对，provider-result-*.json 回执保留，不重复提交。

旧 AI 审核结论保留为历史，不再阻止合规图片继续。旧审核请求结果不明时可点“跳过旧审核，保留图片继续”，旧计费仍记未知；同一任务混有生图或 Shopify 未确认请求时禁止跳过。

重启服务将未完成外部请求标为 uncertain，其余运行任务暂停。已创建 Shopify 商品后不能单图重做；未创建商品时可指定单图重做，旧版保留。主图重做使全部依赖场景、细节和方案失效。画框定位失败保留图片，继续任务可重新定位，不自动重生场景。

## 模型协议与诊断

- 分析：Chat Completions，image_url 输入、JSON object 输出。发送 JPEG 质量 92、4:4:4 副本；坐标提取最长边 2048，原图保留。
- 官方 BigModel GLM-5.3 系列使用 low 推理预算，坐标提取 4096、其他阶段 8192 输出上限；截断不算成功。
- 生图 JSON：model、prompt、aspect_ratio、resolution、n、input_references。
- 生图 multipart：Images Edit 风格，单图 image、多图通常 image[]；代码对 api.vveai.com / api.gpt.ge 使用重复 image 字段。**不发送 `response_format`**：2026-09-10 实测该网关会无视 `response_format=url` 而照旧内嵌返回，只认 `b64_json`；不指定时它偶尔会回图片链接，而链接是可恢复的（回执先落盘、链接 24 小时有效、S3 直链实测 4.3 MB/s），内嵌返回则是"传输断了就全丢"。同次实测：该网关要求单次生成**至少 655,360 像素**，低于此值直接 400 且不计费。若更换服务商，需先核对其 images 接口文档。
- 大尺寸内嵌交付已知风险：2304x2880 的内嵌响应约 15 MB，经网关流回时速率会劣化（实测 2.2 → 1.0 → 0.2 MB/s 直至中断），中断即损失该次生成（图、回执与费用）。若反复出现，优先检查代理节点质量，其次考虑降低目标尺寸。
- 接收 data[0].b64_json 或 HTTPS 图片 URL。下载不携带模型密钥，并校验目标地址；供应商协议兼容性仍需真实验证。
- GPT Image 2 系列发送精确比例、两边均为 16 倍数的尺寸，长边目标 2880（场景 2304x2880、master 2880x1440、PC 首屏 2688x1152）。此前的 2048 目标只产 1600x2000 场景，而主题按 2400 宽取图，等于被放大显示。改尺寸前须核对 Shopify 媒体上限（单文件 20 MB、单边 4472 px、20 MP）；2026-09-10 实测 `gpt-image-2-vip` 采纳 2304x2880 并原样返回，耗时由约 54 秒增至约 104 秒。不支持目标比例时失败，不裁主画凑比例。
- V-API 参考限制、JPEG 上传副本及字段差异为现有适配逻辑，不代表所有服务商规范。
- 保存安全诊断、解析结果、用量及请求回执；网页不能调用 Codex 内置生图。
- 生图成本：服务商返回正数就按它记录（`source=provider`）；当前生图服务商每次返回 cost 0，因此按店主 2026-09-10 提供的单价 **¥0.40 / 张成功生图**记录并标记 `source=owner-estimate`，界面显示"（估）"。不把 0 当作免费，也不把估算伪装成实际扣费；任务详情显示"N 张生成 · 金额"。
- 任务快照（`job.json` 的 `config`）只保存端点、模型与协议，**不保存密钥**：运行时由 `Store.config()` 从 `settings.json` 合并当前密钥，因此轮换密钥对已保存任务立即生效，凭据只存在于 `settings.json`。
- 场景提示词读取 `.agents/skills/canvasra-product/references/scene-lessons.md`。可用环境变量 `CANVASRA_SCENE_LESSONS` 指向其他安装位置的副本；文件缺失时任务以可操作错误失败（不是 ENOENT），不会静默降级场景要求。
